## Context

Hyprland 0.56.2 runs with the legacy parser off, so dispatches are Lua expressions such as `hl.dsp.focus({ workspace = "3" })`. `hyprctl clients -j` reports, per window, `address`, `mapped`, `hidden`, `workspace.id`, `pinned`, `floating`, `at`, `size`, `class`, `title`, `focusHistoryID`, `stableId`, and more. `hyprctl workspaces -j` reports each workspace's `id`, `name`, and `lastwindow`. The session picker already shows the pattern this change copies: a Go command owns the data and the action, and a Quickshell overlay renders it and calls the Go command back.

## Goals / Non-Goals

**Goals:**

- One owner, `internal/space`, for reading Hyprland, ordering the two axes, focusing, and moving a window.
- A navigator whose open, move, carry, cancel, and dismiss are read-only, with Enter and the second `s` of shift mode as the only changes.
- Tests run on fixture JSON and a fake `hyprctl`, never on the live session.

**Non-Goals:**

- A Y axis, a grid, pixel-position ordering, binds, or edits under `~/.config/hypr`.
- Refreshing the list while the navigator is open.

## Decisions

**Z is ordered by `focusHistoryID`, compared within one workspace.** `focusHistoryID` is the window's index in Hyprland's focus history, 0 being the most recently focused window on the desktop. Sorting one workspace's windows by it puts that workspace's most recently focused window in front. On the live session this front window matched each workspace's `lastwindow` on every workspace, including those where the front value was 1 or 3 rather than 0. After a confirm, the chosen window gets value 0, so it is the front app of its workspace on the next list. That is what the operator asked for: the chosen app comes to the front. Alternatives rejected:
- The order of the `hyprctl clients -j` array follows Hyprland's render list. It is not a field, and focusing a tiled window does not move it there, so a confirmed tiled window would not come to the front.
- `stableId` is creation order, not a stack.
- `at` and `size` are pixel geometry, which the operator ruled out as an axis.

Negative `focusHistoryID` (a window outside the history) goes to the back, and ties keep the array order, so the order is total and deterministic.

**Apps are mapped, not hidden windows with a positive `workspace.id`.** Inactive group members are `hidden`, so they are not apps. A pinned window already reports one `workspace.id`, so it lands on one column with no special case. A window whose workspace is missing from `hyprctl workspaces -j`, which can happen when a workspace changes between the two reads, is dropped rather than inventing a column.

**`active` comes from `hyprctl activeworkspace -j`.** It picks the navigator's starting column. Deriving it from `focusHistoryID` 0 would be wrong when the active workspace is empty or a special workspace holds focus.

**Focus checks the target, then dispatches workspace then window.** `space focus` reads a fresh client list and refuses an address that is no longer an app of the named workspace, so a stale navigator cannot move focus somewhere unexpected. The workspace id is re-printed from an integer, and the address must match `0x[0-9a-f]+`, so neither can break out of the Lua string. A dispatch counts as successful only with exit status 0 and an `ok` or empty reply. The operator's own script trusts the exit status, and Hyprland's binary carries `ok` and `hl.focus: window not found` as the replies.

**The overlay unmaps before it focuses.** Hyprland refuses keyboard focus to a window while an exclusive layer surface is mapped ("Refusing a keyboard focus to a window because of an exclusive ls" in the 0.56.2 binary). Enter and Ctrl+M are the same confirm: Ctrl+M is how Enter arrives, and it does not start shift mode. On confirm the chosen satellite first rushes out of its shell toward the eye for 380 ms; then the overlay hides its panel and starts `tesseract space focus` with `setsid -f` so the command outlives the overlay. That command, with `TESSERACT_SPACE_WAIT_LAYER=1`, polls `hyprctl layers -j` until `omarchy-launcher` and `tesseract-space-navigator` are gone, or for two seconds, and only then dispatches. The overlay quits when `setsid` returns. A direct `tesseract space focus` does not set the variable, so it dispatches without polling.

**Shift mode carries a picture, and Hyprland changes once.** The first `s` only records the carried window and where the overlay stood. While a window is carried, the shell draws a derived space: the carried window off its old workspace and put in at the selected workspace and place, the other apps in their order. `h`/`l` and `k`/`j` are the navigation moves over that derived space, so they cycle and count steps as navigation does, and a workspace change lands on the front place. Escape or `q` restores the column and the place the short way round, so the picture eases back. The second `s` is the only write. Put down where it was picked up, it ends the carry. Put down in a new place, the overlay unmaps as it does for Enter and runs `tesseract space move`, which checks the window against a fresh client list and sends the one dispatch `hl.dsp.window.move({ workspace = "<id>", window = "address:<addr>" })`: the stock `hl.dsp.window.move({ workspace = i })` bind from `/usr/share/hypr/hyprland.lua` with the window selector that focus uses. Unmapping first means no exclusive layer surface is mapped when the move runs, so Hyprland does not refuse a focus that comes with it. Alternatives rejected:
- `movetoworkspacesilent` and `hyprctl keyword` are the legacy forms the operator ruled out.
- Dispatching on every carry key would change Hyprland before the operator commits.

**A window put down behind another is focused, not stacked.** `/usr/share/hypr/stubs/hl.meta.lua` names `hl.dsp.window.alter_zorder` and `hl.dsp.window.bring_to_top` only as `fun(...)`, and `/usr/share/hypr/hyprland.lua` never calls them, so their arguments are not documented there and tesseract does not guess them. When `j` or `k` put the window behind another one, or in a new place on its own workspace, the navigator runs `tesseract space focus` after the move, and the window lands on top of that workspace. Z is ordered by `focusHistoryID`, so the focused window is that workspace's front app.

**The carried electron keeps the tight shell.** While a window is carried, the stage lays out the nucleus's apps around it. The carried window stays on the tight shell at the eased depth, and its two electrons cross-fade from the resting place of the slot it leaves to that of the slot it takes, as the selected electron does when the selection moves. Every other app keeps its order and stands one slot further out until the carried window has passed it: it eases across the tight shell as it passes, its electron hides mid-pass, and its ring stays dimmer than the carried one. A carry on Z is therefore one eased step with no swap, and a cycle rolls the two laps of apps as navigation does. At rest the layout equals the plain one, and it holds after a cancel until the depth comes to rest, so a cancel eases back without a jump. The workspace a carried window leaves folds with the gap it left at the tight shell. The carried electron's glow is larger and stronger than the selected one's.

**The overlay draws its own perspective.** Qt Quick 3D is not installed (`/usr/lib/qt6/qml/QtQuick3D` holds only SpatialAudio). `SpaceCamera` is one pinhole camera looking down on the orbit's plane at a shallow tilt of 0.23 rad, about 13°, in logical pixels of a 1280 by 720 stage scaled to the screen, with the nucleus at the origin. Everything is placed through its one `project()`: a sphere is a disc at its projected centre and radius, and a ring is a polyline of projected points, so the near side of the orbit is lower, larger, and wider spaced than the far side. A sphere is glass drawn once with Qt Quick Shapes radial gradients at a fixed size and scaled, and the curve renderer keeps its rim and gradients sharp at any size. Each shell is drawn in two halves, the half behind the nucleus stacked below it and the half in front stacked above it, so a shell passes behind the sphere and in front of it like a ring round a planet. Spheres stack by depth. Alternatives rejected:
- Qt Quick 3D is not installed and is not to be installed.
- Slabs and cards on `Matrix4x4` planes were the rail the operator asked to replace.
- A `Canvas` repaints the whole stage in software on every frame of a move.
- A rounded `Rectangle` laid into the plane draws a ring whose line thickens at the sides and thins at the front.

**One continuous orbit position drives X.** The orbit stands at a real-valued turn, in workspaces, and eases to the selected column over 400 ms with a smoothed ease in and out that keeps its speed when a key retargets it. A workspace's place is a function of its distance from that turn: at 0 it is the nucleus at the centre, from one place out it sits that many steps round the orbit from the front, and in between it swings between the front of the orbit and the centre while it grows or shrinks. The incoming workspace therefore swings round to the front and into the centre while the outgoing one shrinks back onto its place, and every other body moves along the orbit. The step between neighbours is at most 0.72 rad, and smaller with many workspaces so that none rests past 2.9 rad, and a body the opening spin carries past the back of the orbit is hidden until it comes round; lower ids stay left of the nucleus and higher ids right. The workspace nearest the turn owns the shells. They fold into it between 0.06 and 0.42 of a place from the turn, so the owner changes at the halfway point with no shell showing.

**The shells ease along Z.** A shell's radius is a function of its distance from the eased depth: the selected shell is the tight one, each deeper shell is one gap wider with the gaps narrowing outward, and shells more than four beyond the selection fade out. Shells in front of the selection sink exponentially onto the nucleus's skin as faint traces, and their satellites fade. The eased depth moves for 380 ms with a cubic ease-out, so `j` and `k` show as every satellite easing between radii. A satellite rests at a fixed angle by app index, in pairs to the right and the left from the front toward the back, so at any depth the titles in view sit on different sides and at different heights. The workspace leaving the nucleus keeps the depth it showed until the orbit carries it away, and a workspace that comes back mid-turn continues from that depth.

**Scaled text uses curve rendering.** A workspace's name scales with its sphere, so it uses `Text.CurveRendering`, which stays exact at every size. Satellite titles and captions are screen-aligned at a fixed size and keep the default.

**Motion stays quiet.** Opening settles the orbit out of a 1.7 rad spin over 1500 ms while the camera falls in from far back over 1150 ms; after 420 ms the shells unfurl out of the nucleus over 800 ms, their satellites spiralling out to their places. At rest the selected electron swings about 7° each way along its shell over about nine seconds and the halo breathes over about five. Those two clocks also swell the corona, sway two filaments on the rim, walk a shimmer out through the shells and back, and brighten the orbit dust a little. No other clock runs at rest, and a key does not wait on that motion. Enter clears the rest of the system in the first half of the 380 ms rush while the chosen satellite comes toward the eye and to the middle of the stage, and the void clears at the end.

**Axes cycle, and the picture takes the short way.** X is a line of workspaces and Z a stack with a front and a back, and pressing past an end lands on the other end. Only the selection cycles: at rest the orbit keeps lower ids to the left and higher ids to the right, and `SpaceCamera` still keeps far workspaces from turning past the back of the ring. The overlay counts the moves on each axis without wrapping, and the stage eases the orbit and the shells to those counts, so a cycle is one step in the direction of the key. The orbit and the shells are each drawn as two laps of the same workspaces or apps; between the last place of one lap and the first of the next, both laps roll one step on while they crossfade. A cycle past the last workspace therefore turns the orbit one step forward, with the first workspace swinging in from the right, rather than spinning back through every workspace, and a cycle between the deepest app and the front eases one shell. The picture repeats every lap, so a workspace coming back into the nucleus drops whole laps of its held depth and eases from there to its front app. Moving on X resets Z to the new workspace's front app, so Enter right after an X move lands where switching to that workspace would.

**One owner, hosted by a shell.** `SpaceNavigator.qml` holds what `shell.qml` used to hold: the list, the selection, the carried window, the keys, and the focus and move commands, with `SpaceStage` as its only picture. It is a plain Qt Quick item that names no window and never quits. It asks its host to hide before a focus or a move (`hideRequested`), says when the command has run (`finished`), and asks to close on Escape or `q` with no window carried (`closeRequested`). `shell.qml` is now only the overlay's panel: it names the binary from `TESSERACT_SPACE_COMMAND`, passes the keys, hides the panel, and quits. The Super+T launcher in the home repository hosts the same component in its tmux view's center stage. It loads the file by URL from a checkout, because Quickshell cannot import QML from outside a config folder, names its own build, and clears the void with `voidOpacity` so its own backdrop shows. One component keeps the overlay and the launcher from drifting apart in picture or keys. Alternatives rejected:
- A second nucleus drawn by the launcher is a second picture to keep in step.
- Copying the files into the launcher's config folder forks them.

**Package layout.** `internal/space` has no UI dependency and takes an injectable `hyprctl` runner. `internal/spacenav` is the Bubble Tea fallback, rendered through `components/l2` and `components/l3` like the session browser. `internal/quickshell` launches the overlay next to the session picker and reuses its Quickshell command lookup. The overlay lives in `quickshell/space-navigator/` and is embedded with the other assets.

## Risks / Trade-offs

- [The list is read once and can go stale] → `space focus` re-checks the target and refuses a stale one with no dispatch.
- [The unmap and the focus dispatch race] → the focus process starts after a short delay and then needs its own client read before dispatching. Both happen long after a Wayland flush.
- [A future hyprctl changes its success reply] → the check accepts `ok`, case-insensitive, or an empty reply, and requires exit status 0.
- [Enter on a workspace with no windows does nothing] → the CLI form names a window, so an empty column has nothing to confirm. `q` leaves the operator where they were.
- [A host loads the component from outside its config folder] → Quickshell resolves a `Loader` source given as an absolute file URL, and the component's siblings resolve from its own folder; a windowless Quickshell config loaded it that way. A host that cannot load it keeps its own picture.
- [The live overlay takes exclusive keyboard focus, so it cannot be looked at from an agent session] → `SpaceStage` is a plain Qt Quick item with no Quickshell dependency; it was rendered offscreen through Qt's OpenGL renderer with fixture data, at rest, during the open, mid-orbit, at several shell depths, with ten workspaces and a twelve-window workspace, and during the rush.
- [Shift mode cannot be tried on the live overlay from an agent session] → `shell.qml` was driven offscreen through its own key handler with Quickshell stubbed outside the repository, so no layer surface opened: the first pick-up, a carry past the first workspace, a carry through a cycle on Z, both cancels, Enter while carrying, and both put-downs, checking the commands the overlay would run. With no window carried, the stage's shell and electron poses were compared with the stage before shift mode and are identical.
- [A window put down behind another lands on top] → no z-order dispatcher's arguments are documented under `/usr/share/hypr`; the README says the window lands on top.
- [Rings are re-projected on every frame of a move] → each ring half is 49 points from one projection, shells more than four beyond the selection are skipped, and spheres are fixed shapes that only scale; at rest the selected electron, the halo, the corona, the filaments, the shell shimmer, and the orbit dust move, and they share the electron swing and the halo breath.
- [A small or portrait screen] → the stage scales from the 1280 by 720 reference and never below half of it.
